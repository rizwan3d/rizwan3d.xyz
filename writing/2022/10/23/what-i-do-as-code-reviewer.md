### What I do? As Code Reviewer.

Code Review is used to control quality, refactoring, prevent bugs, etc. in code written by other developers before merging it into Master branch.

Sometime developers forget to manage exceptions, handle edge cases, code styling and formatting, memory leak, performance, security, comments, documentation etc. so, code reviewer verify this type of check list.

Following is my check list.

- Verify conflicts in the PRs.
- Verify refactoring.
- Naming, styling and formatting.
- Bool values must begin with is, can, must etc.
- comments must be explanatory but cannot include unnecessary comments.
- Codes with comment lines need to be deleted.
- Unused functions, variables need to be removed.
- Check if all errors are handled.
- Check for implementation of SOLID Principles.
- Verify right use of design patterns.
- Verify performance optimization.
- Verify code sync with existing code patterns/technologies.
- Verify functions/classes/components reasonably small.
- Removed unused packages from project.
- Commits are small and divided into logical parts.
- Commits messages are small and understandable.
- Use branches for new features.
- Code duplications and Reusability.

Actual check list compiled by me include PHP standards (such as PSRs), HTML/CSS and JS/TypeScript. For this article check list just include only generic check that can be imposable on every tech and lang.

Happy Development...
